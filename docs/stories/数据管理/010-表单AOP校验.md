# Story: 表单AOP校验

## 描述
作为业务开发者，系统自动拦截请求并按配置的表单规则校验参数，无需硬编码即可实现接口参数校验。

## 参与者
| 角色 | 说明 |
|------|------|
| 业务开发者 | 定义接口，无需关心校验逻辑 |
| AOP拦截器 | 自动拦截请求并校验参数 |
| 系统 | 后端服务 |

## 流程图
```mermaid
sequenceDiagram
    participant 前端
    participant AOP拦截器
    participant Controller
    participant 验证器工厂

    前端->>AOP拦截器: 发送请求(method+uri+参数)
    AOP拦截器->>AOP拦截器: 匹配FormRuleCache中的规则
    alt 无匹配规则
        AOP拦截器->>Controller: 直接放行
    else 匹配到规则
        AOP拦截器->>AOP拦截器: 解析请求参数
        alt 参数为MultipartFile/HttpServletRequest
            AOP拦截器->>AOP拦截器: 跳过该参数
        end
        AOP拦截器->>验证器工厂: 执行验证器校验
        alt 校验失败
            AOP拦截器-->>前端: 返回R.error(错误信息)
        else 校验通过
            AOP拦截器->>Controller: 放行执行Controller逻辑
        end
    end
```

## 验收标准
- [ ] 规则匹配拦截：Given 请求的method+uri匹配到表单规则, When 请求到达Controller, Then AOP自动拦截并校验参数
- [ ] 校验失败拦截：Given 参数不满足验证器规则, When 校验失败, Then 返回R.error(错误信息)不进入Controller
- [ ] 无规则放行：Given 请求的method+uri无匹配规则, When 请求到达, Then 直接放行执行Controller逻辑
- [ ] 特殊类型跳过：Given 请求参数为MultipartFile/HttpServletRequest, When AOP解析参数, Then 自动跳过这些类型
