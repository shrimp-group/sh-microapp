- 所有 K8s 资源操作实现类均位于 `custom.impl` 包下，实现统一的 `K8sApi` 接口，且禁止在实现类中注入其他 custom 服务。
- REST 层采用 DTO 到 Entity/Param 的显式转换模式，通常借助 `BeanUtil.cp` 完成请求参数到业务对象的映射。
- Service 层对 K8s API 调用产生的 `ApiException` 进行统一捕获，并转换为框架标准的 `SystemException` 或 `ValidationException`。
- 集群客户端连接采用“懒加载 + 定时失效”的缓存策略，在 `KubeConfigHelper` 中通过静态 Map 维护 `ApiClient` 实例。
